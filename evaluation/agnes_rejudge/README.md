# Agnes 未决补判与汇总

本目录提供独立的站内补判工具。它不修改原题、学生作答、既有判分或原始回执；新判决与回执写入独立目录。原记录和旧恢复层必须留在本机；终端只显示中文汇总，不显示题目、答案、密钥或模型响应。

`rejudge.py` 先核验来源、完整 96 份学生作答的身份、请求和回复绑定，并重新计算、验证旧回执恢复层；已有明确对错和能够从旧回执提取的结果不发送给 API。剩余未决默认最多处理 5 份，作为真实环境试点；每份默认一次语义判分，明确无法判断时仍保留未决。连接和格式故障按冻结判分器的重试规则处理，持续异常暂停。`--max-items 0` 才显式启用不限量续跑；任何历史 `null` 结果不会因重复运行而自动重判。

调用的判分器和旧回执恢复器按预设 SHA-256 校验；判分沿用 Agnes 原模型和提示词，仅发送获准的题目、参考答案和学生作答。默认本机最多 5 路，但不能限制同一账号在其他服务器上的并发。程序不能补生成 held / partial 来源，不能保证中断后远端 API 没有执行过请求；原回执保留以供核验。

`summary.py` 是只读汇总：分别列原题和迁移题在前测、对照及后测的判对、判错和未决，并检查原判分、恢复层与补判回执的身份及内容绑定。汇总仅核对本地来源身份与目录结构，未逐条对照冻结的 499 来源清单。状态 `COMPLETE` 或“已扫描”不能证明覆盖完整数据集。

`progress.py` 提供中文表格，显示目标补判进程是否存在及独立决议层的已落盘条数；它不会检查 API 或更改数据。扫描期间写入可能继续，所见为近似快照；正式统计仍使用 `summary.py` 核验绑定。

这两个程序在开发环境只经过合成测试；目标服务器的文件布局、API 连接、限额与模型输出需先完成真实小样本试点。不要把单个模型的判定描述为人工核验。待试点确认数据完整性和服务稳定后，才启动完整续跑；结果持续以本机的独立目录为准。
