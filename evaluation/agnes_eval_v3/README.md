# Agnes 判分修复候选（尚未部署）

此目录是旧判分代码的独立副本，不改动运行中的代码、旧数据、结果或控制器。`agnes_judge.py` 保留既有模型、题目和学生作答三字段、请求哈希、身份绑定、结果及回执路径；`watch_sources.py` 保持原数据源与结果目录布局。

新解析版本 `agnes_full_response_v2_topbool_v1` 接受单独 JSON 布尔 `true` / `false` 和旧版 `{ "correct": true/false }`，对 HTTP JSON 外层响应及判分正文任意嵌套层的重复 JSON 键予以拒绝。显式 JSON `null` 与 `{ "correct": null }` 仍为未决、不因格式重试。长度截断、空正文、非 JSON、重复键、响应结构缺失和 schema 无效，记录原响应并最多额外重试三次（原请求加三次合计最多四次）；模型名不匹配或其他 finish_reason 则不被当作明确判决。每次调用可多次计费，超时重试不能保证远端仅执行一次，本地按身份和 put-once 保证结果不覆盖。原已落盘 RESULT（包括 unknown）仅核对绑定后原样复用，永不覆盖。单条新版结果记录 `parser_version`，来源汇总中的 `completion_parser_version` 只表示汇总完成程序的解析版本，不暗示混合来源中每条都是新版。

返回有效布尔时才增加并发；HTTP 200 但内容无效或显式未决时并发窗口保持不变，不触发网络退避；请求错误、429、5xx 沿用原有降窗和退避。进入冷却后，冷却期内此前在途的成功响应不会抵消刚刚降下的窗口或清除错误次数。共享锁目录在单服务器上最多 5 个并发；其他服务器共享账号时无法仅凭本机锁约束全账号并发。

运行 `python3 -m unittest -v test_repair` 仅使用合成数据和模拟 API，可验证格式、最多 4 次、已有数据不重判、恢复、并发上限和混合来源；未在远端进行实时 API 或 GPU 联调。旧判分进程与新进程不能同时运行写同一位置：v4 监督器会自动拉起旧进程，必须经单写者、安全停机交接，先排空旧判分任务并避免监督器重启旧进程；不能只杀 watcher 或直接覆盖其代码。终端超时和服务崩溃发生在远端处理后但回执落盘前时，本地无法知道服务端是否处理过该次请求；需保留意图和重试记录。

独立恢复层曾从旧 unknown 的顶层布尔提取候选，但不会被旧状态页自动合并。新版仅修新请求和安全恢复未完成回执，不改旧 unknown；需单独合并统计并标明解析版本。格式兼容不是判分数学准确性的证明。
