# Elastic shared-service evaluation (independent experimental launcher)

The launcher waits until at least two fully idle A100 80GB GPUs are available. It selects a topology once at startup: two GPUs run one teacher and one student shared by all three process-isolated difficulty evaluators; three GPUs run two teachers and one student, with EASY/HARD sharing one teacher; four GPUs run three teachers and one student; five or more free GPUs run three teachers and two students. It does not add GPUs dynamically after launch. The shared teacher vLLM retains `--max-num-seqs 1`, so independent dialogues queue rather than execute concurrently on one teacher. Student samples retain four requests per evaluator, up to 12 aggregate requests on a shared student service.

The original frozen evaluation code, prompts, samples and completed grading results are retained; pending/held records with potentially sent requests are not blindly replayed. A single grader is used; technical failures, genuine ambiguous answers and historical unknown results have different handling. The launch validates files, device identities, source and stage locks. It executes synthetic service smoke and at most one new source per difficulty, then checks the resulting scoring receipts before continuing bulk work. The new topology and code hash are saved in a separate execution receipt. Concurrent request ordering and vLLM scheduling may change sampled text despite fixed seeds, so the topology must be reported with the results.

Real GPUs, teacher queue delays, 20k context memory, student throughput and full user workloads have not been tested in the target container; the smoke is not a substitute for the real-source trial. GPU availability checks are snapshots and do not reserve cards atomically across users. The existing four-GPU waiter must be safely stopped while still waiting and must release locks before this launcher starts. A stopped terminal does not stop a nohup process, but a stopped Docker container does. The new supervisor should write its aggregate log to `/workspace/results/own-test-499-v1/shared-supervisor-elastic.log`; status.py reads only fixed labels from that path.

Run offline tests with `python3 -m unittest -v test_supervisor test_status test_wait test_elastic` from this directory. Tests use synthetic data and mock local services; they do not call a real API or GPU.
