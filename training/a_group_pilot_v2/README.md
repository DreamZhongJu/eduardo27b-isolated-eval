# A 组单机试点启动器（待 A100 实测）

此脚本在全新试点目录尝试用作者原始训练代码、BF16 和 4 至 6 张 GPU 做 1 步或 10 步试点。它不是经过 A100、Ray 和 vLLM 联合训练验证的正式启动器。需等新训练环境安装完成、作者题池成功生成后才能试用；目标服务器每张卡必须得到实际占用授权。

v2 修正学生服务模型名：vLLM 注册名与作者对话配置中根据 USER 构造的名称一致，并且与奖励函数一致。服务登录密钥由本次进程临时产生，不写入命令或仓库。

`--wait-gpus` 自动等待 4 张以上候选空闲 A100 80GB，最多选 6 张。4 卡时导师 2、学生 1、裁判 1；5 卡时 2+1+2；6 卡时 2+2+2。4 卡裁判单卡能否加载仍需实际验证。也可用 `--gpus 0 1 2 3` 显式指定 4 至 6 张卡。连续检查显存仅少量系统开销、利用率为零且无可见计算进程；共享机器上不同容器的进程可能不可见，别人的任务也可能在检查后启动，此检查不能代替调度器独占。

流程：作者训练数据哈希和代码版本检查 -> 学生和裁判服务启动 -> 两个模型虚构题回复 -> 真实训练。每道原题生成 16 段对话、通过门槛后学生作答 16 次；1 步试点保存检查点，10 步试点结束后停止。GPU 训练本身可能很慢。此脚本只处理独立试点，不可用于正式 100 步。只绑定回环地址并使用临时 API 令牌。正常结束或常见异常时向已启动的服务进程组发送停止信号；容器被强杀时需人工核对 GPU 和残留。脚本不执行 `ray stop -f`，但 Ray 后台资源是否彻底退出要在目标机器实测确认。

数据使用 `/workspace/A_group_repro_20261117/data/author_prepared`，该目录须由作者题池转换脚本生成；各输入 parquet 校验哈希。环境脚本的状态必须为“完成”。使用 Ray local 和作者 DPPO 配置，教师服务和环境与论文不同之处留在独立目录中的偏离记录。正式效果、训练精度和 GPU 内核适配只有真实端到端运行才能评价。

## 示例（仅在训练环境验证后，必须换成实际空闲卡号）

```bash
mkdir -p /workspace/A_group_repro_20261117/pilots
nohup /workspace/A_group_repro_20261117/envs/env-candidate-vllm0191/bin/python \
 /path/to/pilot.py --wait-gpus --steps 1 --name smoke1 \
 > /workspace/A_group_repro_20261117/pilots/smoke1-launch.log 2>&1 < /dev/null &
```

目录不能覆盖已存在的同名试点。`status.py smoke1` 输出阶段与进程状态，具体训练日志保留在目标服务器。若缺卡、环境不兼容或服务加载失败则停止，不修改已有文件；排查后使用新名称重试。

`test_pilot.py` 仅对命令和目录规则做 CPU mock 测试，不证明真实 GPU 运行成功。
