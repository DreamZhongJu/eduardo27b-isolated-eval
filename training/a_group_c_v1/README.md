# A 组 C 单步试验

审核配置见 [DEVIATIONS.md](DEVIATIONS.md)。本次使用已完成 B 验收的 A100 容器和冻结题池。控制器运行一次 Tutor 更新、作者末步验证和一个 CPU 权重合并。全程本机推理。控制器沿用 df72ec9 的训练退出分类。

| 操作 | 容器内入口 |
|---|---|
| 查看 B 的第 1 步梯度、损失、学习率、放行数，及挂载盘空间和四个目录去重总大小 | 候选环境 Python 执行 b_numbers.py |
| 启动 C | bash start_c.sh |
| 查看 C | 候选环境 Python 执行 c_status.py --work /workspace/A_group_repro_20261117/pilots/c_paper_v1 |
| 收尾报告 | 本次工作目录的 C阶段报告.md、C统计.md、deviations.md |

开始后沿用 A 阶段验证的占卡代码和同一个控制器锁。角色为两张 Tutor 整卡、一张裁判整卡及一张有至少 40 GiB 空闲显存的学生卡。凑卡每轮上限 45 分钟，释放本任务已占设备后随机等 5 至 15 分钟。裁判和学生分别健康后再交接 Tutor。三次交接复核失败结束本次运行。每十秒检查技术 fallback；训练或验证中观测到一次即停止。未触发自动重新训练。

成功路径会记录训练器自然退出、依次停止学生与裁判、各直接子进程的带符号退出码及观察时间，随后用 veRL CPU 合并工具读取第 1 步权重。技术异常保留已有状态。角色退出时设备归属无法证明则显存峰值显示未知。CPU 合并抽读每片一个数值、检查配置与索引；来源检查包括两片模型以及优化器、额外状态、数据加载器共五个状态文件。C 只验证末步一次自动合并。正式运行的多次导出、保留和中断续跑仍待决策。

请求数来自两个本地服务已响应的 chat/completions POST。每条日志增加服务器响应时间戳。按冻结的训练与验证原题归属核对轨迹，再用同步保存的检查点时点区分两阶段的请求。缺失证据显示未知，报告不足以验收时单列说明。训练 step 和 testing 两个计时单列，save_checkpoint 已包含在 step 中。对话内容仅在容器内用于计数。对外只需汇总表，保留原始文件在服务器。

B 对第 1 步训练器数值只读提取。只有两步的检查点时间、唯一对话、来源和分组均能支持归步时才显示准确放行数。所需四个数字取自目标机；相关系数与同步耗时单独不足以验证实质更新后的权重同步。
