# A 组单步共享显卡试点（候选）

参考作者训练脚本，单步运行，BF16、原始 Tutor rollout 内存比例 0.58，每题 16 条教学轨迹。只使用四张 A100：Tutor 两张、学生和裁判各一张。并发和显存分配不同于独占卡的实现，不自动更改训练超参数。

启动前连续两次查询 `nvidia-smi`，只检查总量 80GB 和空闲显存，允许其他进程及非零利用率。Tutor 各需 64 GiB 空闲，学生 40 GiB，裁判 72 GiB；动态分配教师2 / 学生1 / 裁判1。学生 vLLM 利用率 0.40、裁判 0.78，以 GPU 总显存为预算；最多 64 并发序列。训练过程中每2秒查询，空闲显存低于8 GiB时只停止本任务。运行中其他人的显存也可能变化，这些阈值不是保证，FSDP 动态显存没有总硬上限，采样间隔不能消除 OOM 或对别人作业产生影响的风险。若 GPU不足则等待。

不进行逐卡显存预留。`check_lock.py` 只判断旧试点锁，不停止旧任务；存在旧任务时禁止双开。原数据和作者源码不修改，所有记录与文件落 A 组目录。新 vLLM budget 和角色是待目标 A100 验证的条件，失败按错误输出排查。

CPU 模拟测试：`python3 test_shared.py`，不调用GPU，不含真实运行验证。按用户原计划，单步过后还要10步试运行，正式100步另需阶段批准。
